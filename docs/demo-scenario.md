# 5분 시연 대본

현재는 구현 후 사용할 대본입니다. 화면 이미지나 실행 결과가 아닙니다.

## 준비

고정 기준 시각 2026-09-05 Asia/Seoul, 합성 장애 4건과 매뉴얼 2종을 적재합니다. operator로 접속하고 활성 문서·모델 버전을 확인합니다. 이전 티켓이 있다면 새 실행으로 데모하거나 명시적인 데모 초기화를 수행합니다.

## 0:00–1:00 문제와 조회

“문서와 장애 시스템을 따로 확인하던 작업을 한 흐름으로 연결했습니다.”

질문: “2026년 8월 P1 네트워크 장애를 요약하고 매뉴얼대로 대응 방안을 알려줘. 미해결이면 후속 티켓을 만들어줘.”

예상 조회: INC-014(OPEN), INC-015(RESOLVED). 7월 장애와 SERVER 장애는 제외되어야 합니다. 장애 상태/원인은 Spring 조회 결과임을 보여줍니다.

## 1:00–2:00 근거

네트워크 운영 매뉴얼의 제목·버전·섹션과 원문 발췌를 펼칩니다. 검색 distance를 정확도라고 설명하지 않습니다. 답변의 장애 사실과 문서의 권고 절차를 구분합니다.

## 2:00–3:00 승인

INC-014의 티켓 초안을 펼치고 아직 티켓이 없음을 확인합니다. 승인 후 실제 ticket_id를 보여줍니다. 같은 요청을 재전송해도 ticket_id가 유지됨을 검증 결과와 함께 설명합니다. UI 버튼 비활성화만으로 중복을 막는 구조가 아님을 설명합니다.

## 3:00–4:00 실패와 제약

새 실행에서 거절 → 티켓 0건. “사내 우주선 운영 규정은?” → 관련 문서 부족. viewer 계정은 승인 불가. 연결 실패는 업무 데이터가 없다는 답으로 바뀌지 않아야 합니다.

## 4:00–5:00 운영 증거

request_id로 AI/Spring 로그를 연결하고, 실제 평가 보고서와 재시작 복구 테스트 결과를 보여줍니다. 아직 측정하지 않은 항목은 시연 성과에 포함하지 않습니다.
