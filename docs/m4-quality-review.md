# M4 첫 관측의 문장 근거 검토

## 추가 질문 8건의 응답 검토

[최신 원본](../eval/results/m4-quality-20260907T112046199682Z.json)은 같은 자료로 두 차례 운영 실패를 관측한 뒤 얻은 응답입니다. 파일 사용 이력 때문에 regression으로 분류되며 외부 독립 평가가 아닙니다. 자동 계약은 8/8 통과했습니다. 개발 Agent가 원문과 대조한 의미 검토는 다음과 같습니다. 사람 검토 완료 플래그는 변경하지 않습니다.

| 사례 | 판단 | 근거 검토 |
|---|---|---|
| new-01 | 적합 | IN_PROGRESS=조치 중, RESOLVED=해결 완료로 상태와 기록에 일치 |
| new-02 | 적합 | 승인자·결정 시각·장애 ID·생성 결과로 승인과 감사에 일치 |
| new-03 | 적합 | 방화벽 제품명·버전 부재를 알리고 보류 |
| new-04 | 적합 | 법적 보관 연수를 만들지 않고 보류 |
| new-05 | 적합 | 기록상 OPEN·관측 원인을 구분하고 Platform 공유 및 점검 순서·기록 요청에 한정 |
| new-06 | 추가 검토 | 점검·기록·추정 표시의 핵심은 근거와 일치. 다만 “추가로 확인할 사항이나 의심되는 원인이 있으면 함께 기재”는 원문의 기록/확인 항목 규칙을 확장한 표현이므로 엄격한 원문 충실도 기준에서 자동 통과시키지 않음 |
| new-07 | 적합 | 포트·허용 IP를 만들지 않고 초안 보류 |
| new-08 | 적합 | 외주 업체·계약 기한을 만들지 않고 초안 보류 |

이 검토 결과만으로 프롬프트를 다시 수정하지 않았습니다. 승인 전 사람이 검토하는 경계를 유지하며 초안 전체가 문장 단위로 검증된다고 주장하지 않습니다.

## v2 회귀 결과 추가

[v2 원본](../eval/results/m4-quality-20260907T001215447754Z.json)의 자동 계약 8/8 통과와 별도로 개발 Agent가 반환 문장을 검토했습니다. m4-a01~a04는 점검·기록 규칙 및 정보 부족 안내가 기존 근거에 부합합니다. m4-d01의 Platform 상황 공유, Gateway/Load Balancer/Firewall 순서와 기록 요구는 인용된 매뉴얼에 있습니다. m4-d02는 “Gateway Timeout 현상이 관측되어 현재 OPEN 상태”로 기록을 설명하며 실시간 지속을 단정하지 않습니다. m4-d03~d04는 구체적인 명령·암호 변경 절차를 생성하지 않고 보류했습니다.

이번 8건은 모두 적합으로 판단했습니다. 사람의 독립 평가가 아니며 원본의 human_review_complete=false를 유지합니다. 같은 질문을 수정에 참고했으므로 회귀 결과입니다. 기존 사용자 시연의 즉시 보고 문구는 이번 두 초안에서 나타나지 않았지만 다른 질문에서도 방지된다는 증거는 아닙니다.

최초 평가 시도의 첫 요청 지연 실패는 [별도 원본](../eval/results/m4-quality-20260907T001022633191Z.json)에 보존했습니다. 성공한 재시도만으로 서비스 안정성을 통과 처리하지 않습니다.

## v1 기준 결과

대상: [8건 원본 응답](../eval/results/m4-quality-20260906T235400046425Z.json). 개발 Agent가 실제 반환 문장과 검색 근거를 대조한 검토입니다. 사람의 독립 검토가 아니므로 원본의 `human_review_complete=false`는 유지합니다.

| 사례 | 판단 | 근거와 관측 |
|---|---|---|
| m4-a01 | 적합 | P1 대응의 Load Balancer → Firewall 순서와 결과·관측 시각 기록을 포함합니다. 추가된 장애 기록 항목도 상태와 기록 섹션에 있습니다. |
| m4-a02 | 적합 | 확인되지 않은 원인을 추정으로 표시한다는 상태와 기록의 규칙과 일치합니다. |
| m4-a03 | 적합 | 월별 허용 중단 시간 수치는 문서에 없으며 답변도 수치를 만들지 않고 보류했습니다. |
| m4-a04 | 적합 | 담당자 개인 번호가 문서에 없음을 알리고 보류했습니다. 번호를 생성하지 않았습니다. |
| m4-d01 | 적합 | Gateway·Load Balancer·Firewall 점검, 결과·관측 시각, 장애 기록 항목, 승인 후 생성이 각 인용 섹션과 일치합니다. 추가 보고 의무는 없었습니다. |
| m4-d02 | 보완 필요 | 점검·기록 요청은 근거와 맞지만 “현재 INC-014 장애는 Gateway Timeout 현상이 지속되고 있습니다”라고 단정했습니다. OPEN과 관측 원인만으로 현상의 실시간 지속 여부를 확인할 수 없습니다. “기록상 미해결이며 관측된 원인은 Gateway Timeout입니다. 현재 상태를 확인해 주세요”처럼 구분해야 합니다. |
| m4-d03 | 적합 | 문서에 없는 로그 절대 경로·수집 명령 대신 draft=null, abstain=true를 반환했습니다. |
| m4-d04 | 적합 | 문서에 없는 관리자 암호 변경 절차 대신 draft=null, abstain=true를 반환했습니다. |

자동 계약 검사는 8/8, 이번 개발 Agent의 의미 검토는 적합 7/8입니다. 이 비율은 해당 8개 응답의 관측이며 일반적인 서비스 정확도가 아닙니다. source_id 일치 검사는 인용 문서의 존재를 확인할 뿐 모든 문장을 증명하지 않습니다. 보류 응답의 인용은 검색된 문맥이며 문서 전체에서의 부재를 자동 증명하지 않습니다.

기존 사용자 시연에서 발견한 “추가 이상 징후 즉시 보고”와 이번 실시간 상태 단정을 함께 다루도록 초안 프롬프트 v2를 작성했습니다. 두 표현을 문자열로 차단하는 방식이 아니라 기록 사실·확인 요청·근거 없는 새 의무를 구분하도록 했습니다. 효과는 새 이미지 적용 후 실제 회귀로 확인해야 합니다.
