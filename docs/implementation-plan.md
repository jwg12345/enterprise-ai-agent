# 구현 순서와 완료 조건

## M0 — 현재 완료

한글 문서 5종, API 계약, 시연 대본, 합성 데이터, 평가 샘플, 서비스별 구현 위치, 문서 검사 CI를 준비합니다. 서비스 실행 파일을 만들어 둔 단계는 아닙니다.

## M1 — 실행 기반과 업무 조회 (완료)

의존성 고정 → FastAPI/Spring/Streamlit 기동 → PostgreSQL migration·seed → 인증된 장애 조회 → UI 표 → Compose·pytest/JUnit·CI 순서로 진행합니다. [첫 작업 프롬프트](../prompts/codex-first-task.md)를 사용합니다.

완료 조건: 새 환경에서 동일 합성 데이터를 조회하고 실패·권한 검사 및 실제 DB 통합 검증을 통과합니다. 문서 검색이 없는 M1과 최종 readiness 조건을 분리해 기록합니다.

## M2 — RAG와 읽기 Agent

문서 정규화·BGE-M3 명시적 embedding·Chroma 적재 → LangGraph 조회/검색/답변 → 출처 검증 → Streamlit 채팅·근거 화면. 테스트 LLM과 실제 LLM 설정을 분리합니다.

완료 조건: 네트워크 질문에서 실제 적재 문서를 검색하고, 근거 없는 질문에는 보류하며, 도구/문서 내 공격 지시가 도구 실행 권한을 바꾸지 않습니다. 모델 다운로드 시간과 메모리를 기록합니다.

## M3 — 영속 승인과 업무 쓰기

승인 원장·티켓 migration → 초안 해시·권한·만료 → interrupt/checkpointer → 승인 UI → 멱등 쓰기 → 복구 작업.

완료 조건: 승인 전·거절·만료 0건, 정상 승인 1건, 동시 요청/재시도 1건, 다른 사용자 거절, AI 재시작 복구, 커밋 직후 응답 유실 복구를 실제 DB로 검증합니다.

## M4 — 운영 검증과 포트폴리오

고정 평가셋 확대 → 평가 실행기 → 품질/지연 측정 → health 및 장애 복구 → 시연 캡처 → README 결과 업데이트.

완료 조건: 버전·환경·분모가 있는 평가 보고서, 실패 사례, 재현 가능한 실행 설명, 합성 데이터로 촬영한 승인 시연을 제공합니다. GitHub 저장소 생성·원격 업로드는 별도 후속 작업입니다.

현재 M1은 로컬 Compose·실제 DB·브라우저 검증까지 완료했습니다. [검증 결과](validation-m1.md)를 참고하고 다음은 M2를 진행합니다.
